# 功能規格：應徵者作答介面模組化

**功能分支**：`002-candidate-assessment-ui`

**建立日期**：2026-08-03

**狀態**：草稿（v1）

**輸入**：將「應徵者面試／作答介面」獨立成清楚、可單獨開發與驗證的前端模組

**上游規格**：本規格為 [001-ai-recruitment-assessment](../001-ai-recruitment-assessment/spec.md)
的**前端結構重構**，不新增任何業務行為。上游 FR-004、FR-018、FR-029～FR-035、
FR-047、FR-049～FR-052 的行為在本次變更前後必須完全等價。

## 背景與問題陳述

應徵者是本系統唯一的外部使用者，也是唯一不需帳號、僅以 URL token 識別身分的角色。
但目前的前端結構把三種角色混在同一層：

```text
frontend/
├── index.html        HR
├── manager.html      主管
├── assessment.html   應徵者          ← 與內部介面同層
└── js/
    ├── api.js        三種角色共用
    ├── hr.js         HR
    ├── manager.js    主管
    ├── editor.js     應徵者（233 行，同時負責載入、狀態判定、渲染、試跑、提交）
    └── chat.js       應徵者（模組載入時即抓取 DOM，與特定 HTML 綁死）
```

由此產生四個具體問題：

1. **產品邊界不清**：應徵者介面是對外產品入口，卻與內部管理介面混在同一目錄，
   無法單獨開發、單獨檢視變更範圍、單獨稽核「有沒有洩漏內部資料」。
2. **模組邊界不清**：`editor.js` 一個檔案同時承擔連結解析、session 載入、
   狀態判定（逾期／已提交／題目準備中）、DOM 渲染、CodeMirror 掛載、
   試跑、提交七件事，且全部與 `document` 直接耦合。
3. **無法驗證**：狀態判定與錯誤處理是應徵者體驗的核心，卻沒有任何自動化測試——
   因為邏輯全部埋在 DOM 事件處理器裡，無法在沒有瀏覽器的情況下呼叫。
4. **錯誤處理有缺口**：已載入頁面後若後端回 409（已提交）或 410（逾期），
   目前只會把訊息塞進執行結果區塊，畫面仍停留在可作答狀態；
   `session.chat_history` 已由後端回傳但前端完全未使用，重新整理即遺失對話。

## 使用者情境與測試 *(必填)*

### 使用者故事 1 — 應徵者開啟連結並看到正確的畫面狀態（優先級：P1）

應徵者點開信件中的連結後，頁面必須明確告訴他現在能做什麼：可以作答、題目還沒準備好、
連結已逾期、或是已經提交過了。任何情況下都不得看到空白頁或技術性錯誤訊息。

**為何是此優先級**：這是應徵者接觸系統的第一秒。狀態判斷錯誤會直接造成客訴，
而且它是其餘所有故事的前置條件。

**獨立測試方式**：以「有效連結／缺 token／不存在的 token／逾期連結／未指派題目／
已提交」六種輸入呼叫狀態判定模組，可在無瀏覽器環境下驗證其輸出，不需後端參與。

**驗收情境**：

1. **Given** 連結不含 `token` 查詢參數，**When** 頁面載入，**Then** 顯示
   「連結不完整」提示，且**不得**發出任何 API 請求。
2. **Given** token 有效且狀態為待作答，**When** 頁面載入，**Then** 顯示作答工作區，
   並顯示職缺名稱、連結到期時間與剩餘試跑次數。
3. **Given** 後端回應 410，**When** 頁面載入，**Then** 顯示逾期提示與「聯繫 HR」指引，
   且工作區保持隱藏、題目內容不被渲染。
4. **Given** 後端回應 404，**When** 頁面載入，**Then** 顯示「找不到此測驗連結」，
   訊息中不得包含 token 值本身。
5. **Given** 狀態為 `PENDING_ASSIGN`，**When** 頁面載入，**Then** 顯示「題目準備中」，
   而非空白頁面。
6. **Given** `submitted_at` 不為空，**When** 頁面載入，**Then** 顯示已完成提交與提交時間，
   工作區保持隱藏。
7. **Given** 後端回應 500 或網路中斷，**When** 頁面載入，**Then** 顯示可重試的一般性錯誤，
   不顯示原始例外內容。

---

### 使用者故事 2 — 工程類應徵者撰寫程式碼並試跑（優先級：P1）

工程職缺的應徵者看到程式碼編輯器、語言選擇與試跑按鈕，可在提交前反覆驗證程式行為，
並清楚知道還剩幾次試跑機會。

**為何是此優先級**：這是工程類考核產生評測素材的主要途徑，也是應徵者停留最久的畫面。

**獨立測試方式**：試跑結果的呈現（輸出、錯誤、終止原因、耗時、截斷）與剩餘次數推進
皆為純函式，可獨立輸入 `ExecutionResult` 物件驗證輸出字串與次數變化。

**驗收情境**：

1. **Given** 部門類型為工程類，**When** 畫面渲染，**Then** 顯示程式碼編輯器、語言選擇、
   標準輸入欄位與試跑按鈕。
2. **Given** CodeMirror 的 CDN 不可用，**When** 編輯器掛載失敗，**Then** 退回純文字輸入框，
   作答能力不受影響。
3. **Given** 應徵者切換語言，**When** 編輯器重新掛載，**Then** 已輸入的程式碼不遺失。
4. **Given** 試跑成功，**When** 結果回傳，**Then** 顯示標準輸出與錯誤輸出、
   終止原因的中文說明、執行耗時，並在輸出被截斷時明確標示。
5. **Given** 試跑回傳編譯錯誤，**When** 結果顯示，**Then** 呈現為「編譯／語法錯誤」
   與錯誤訊息，而非系統故障。
6. **Given** 試跑成功，**When** 結果顯示完成，**Then** 剩餘試跑次數減一並更新於畫面。
7. **Given** 剩餘試跑次數為 0，**When** 畫面更新，**Then** 試跑按鈕停用，
   但提交按鈕維持可用。
8. **Given** 後端回應 429，**When** 錯誤處理，**Then** 剩餘次數歸零、試跑按鈕停用、
   提交按鈕維持可用，並顯示後端訊息。
9. **Given** 後端回應 503（沙箱不可用），**When** 錯誤處理，**Then** 顯示沙箱不可用訊息，
   並明確告知仍可提交；剩餘試跑次數**不得**被扣減。
10. **Given** 試跑請求進行中，**When** 應徵者再次點擊試跑，**Then** 不得送出第二次請求。

---

### 使用者故事 3 — 非工程類應徵者以文字作答（優先級：P1）

非工程職缺的應徵者看到的是純粹的文字作答介面，畫面上不出現任何與程式碼執行有關的元素。

**為何是此優先級**：與 US2 同為作答主線，且錯誤地顯示程式碼介面會讓非工程類應徵者
無法完成考核。

**獨立測試方式**：以 `dept_type` 為 `NON_ENGINEERING` 的 session 物件輸入視圖模型，
驗證其輸出標示為非工程類且不含語言欄位。

**驗收情境**：

1. **Given** 部門類型為非工程類，**When** 畫面渲染，**Then** 顯示文字作答區，
   且語言選擇、試跑按鈕、標準輸入與執行結果區塊皆不顯示。
2. **Given** 非工程類應徵者提交，**When** 送出請求，**Then** 請求中的語言欄位為空值。

---

### 使用者故事 4 — 應徵者確認後提交作答（優先級：P1）

應徵者提交前必須經過一次明確確認，提交成功後畫面轉為唯讀並顯示成功訊息。

**為何是此優先級**：提交是不可逆的單次動作（上游 FR-034），誤觸的代價由應徵者承擔。

**獨立測試方式**：提交結果與各種失敗回應的畫面轉換皆由純函式決定，可獨立驗證。

**驗收情境**：

1. **Given** 應徵者點擊提交，**When** 確認對話出現，**Then** 明確告知提交後無法修改，
   且需明確確認才會送出請求。
2. **Given** 應徵者在確認對話中取消，**When** 對話關閉，**Then** 不送出任何請求，
   作答內容保持不變。
3. **Given** 提交成功，**When** 回應回傳，**Then** 工作區隱藏並顯示含提交時間的成功訊息。
4. **Given** 提交請求進行中，**When** 應徵者再次點擊提交，**Then** 不得送出第二次請求。
5. **Given** 後端回應 409（已提交），**When** 錯誤處理，**Then** 畫面轉為「已提交」唯讀狀態，
   而非停留在可作答狀態。
6. **Given** 後端回應 410（逾期），**When** 錯誤處理，**Then** 畫面轉為逾期狀態。

---

### 使用者故事 5 — 應徵者與 AI 助教對話（優先級：P2）

應徵者可在作答中向 AI 助教提問取得觀念引導；助教故障時不得影響作答、試跑與提交。

**為何是此優先級**：提升體驗並產生評估素材，但非完成考核的必要條件（上游 US7）。

**獨立測試方式**：對話模組可在不依賴其餘畫面的情況下掛載於任意容器並驗證其錯誤隔離行為。

**驗收情境**：

1. **Given** 頁面載入時 session 已含歷史對話，**When** 畫面渲染，**Then** 完整還原先前的
   問答內容並依時間排序（目前版本會遺失此資料）。
2. **Given** 應徵者送出問題，**When** 等待回覆，**Then** 顯示等待中的暫時訊息。
3. **Given** 助教回覆觸發護欄，**When** 回覆顯示，**Then** 附註說明助教僅提供觀念引導。
4. **Given** 助教回應 503，**When** 錯誤處理，**Then** 錯誤僅呈現於對話區塊，
   且作答、試跑、提交按鈕仍全部可用。
5. **Given** 對話請求進行中，**When** 應徵者重複送出，**Then** 不得送出第二次請求。

---

### 使用者故事 6 — 開發者可單獨開發與驗證應徵者介面（優先級：P2）

開發者可在不碰觸 HR 與主管介面的前提下修改應徵者介面，並以自動化測試驗證其行為。

**為何是此優先級**：這是本次重構的直接目的；但對終端使用者無立即可見價值，故列 P2。

**獨立測試方式**：以靜態掃描驗證目錄邊界與匯入邊界，以單元測試驗證純邏輯模組。

**驗收情境**：

1. **Given** 應徵者介面的所有檔案，**When** 檢視目錄，**Then** 全部位於單一資料夾內。
2. **Given** 應徵者介面的原始碼，**When** 靜態掃描，**Then** 不含任何直接的 `fetch(` 呼叫。
3. **Given** 應徵者介面的原始碼，**When** 靜態掃描其匯入，**Then** 不匯入 HR 或主管模組，
   且自共用 API 模組只取用應徵者相關的匯出。
4. **Given** HR 與主管介面的原始碼，**When** 靜態掃描其匯入，**Then** 不匯入應徵者模組。
5. **Given** 純邏輯模組，**When** 於無瀏覽器環境執行測試，**Then** 可直接匯入並驗證，
   不需要 DOM。

---

### 邊界情況

- **舊連結**：7 天效期內已寄出的連結指向舊路徑，路徑變更後必須仍可送達作答頁面，
  且 `token` 查詢參數必須完整保留。
- **URL 命名空間相撞**：靜態頁面路徑與後端 candidate API 路徑共用同一前綴，
  頁面路徑不得遮蔽 API 路由。
- **CDN 全面不可用**：字型與 CodeMirror 皆自 CDN 載入；兩者皆失敗時，
  頁面必須仍可讀、可作答、可提交（字型與語法標示降級可接受，功能不可降級）。
- **session 內含未預期欄位**：即使後端未來多回傳欄位，應徵者介面也只呈現白名單內的欄位。
- **題目含未跳脫字元**：題目描述、限制條件與範例測資中的 HTML 特殊字元必須以文字呈現，
  不得被當作標記解析。

## 需求 *(必填)*

### 功能需求

#### 目錄與產品邊界

- **FR-101**：應徵者介面的所有檔案（HTML、JS 模組、樣式、測試）必須集中於單一資料夾
  `frontend/candidate/`，與 HR、主管介面在檔案結構上分離。
- **FR-102**：應徵者介面的模組**不得**匯入 HR 或主管的模組；HR 與主管的模組
  **不得**匯入應徵者的模組。此限制必須以自動化檢查強制執行，而非僅靠慣例。
- **FR-103**：應徵者介面自共用 API 模組取用的匯出，必須限於應徵者相關的項目
  （`candidate` 命名空間與錯誤／格式化工具），**不得**取用 `hr` 或 `manager` 命名空間。
- **FR-104**：應徵者介面**不得**出現任何直接的 `fetch` 呼叫；所有後端存取一律經由
  `frontend/js/api.js`。此限制必須以自動化檢查強制執行。

#### 路徑與相容性

- **FR-105**：應徵者作答頁的正式路徑為 `/candidate/assessment.html`。
- **FR-106**：舊路徑 `/assessment.html` 必須保留為轉址頁，將 `token` 查詢參數
  原樣轉送至新路徑，使已寄出的連結不失效。
- **FR-107**：新增的靜態頁面路徑**不得**遮蔽既有的 candidate API 路由；
  `/candidate/session/{token}` 必須仍回傳 API 回應。

#### 畫面狀態

- **FR-108**：應徵者頁面必須具備明確且互斥的畫面狀態集合：
  `LINK_INCOMPLETE`（連結不完整）、`NOT_FOUND`（連結不存在）、`EXPIRED`（逾期）、
  `PREPARING`（題目準備中）、`SUBMITTED`（已提交）、`READY`（可作答）、
  `LOAD_FAILED`（載入失敗）。
- **FR-109**：畫面狀態的判定必須由不依賴 DOM 的純函式決定，其輸入為 session 資料
  或 API 錯誤，輸出為狀態與對應訊息。
- **FR-110**：`READY` 以外的所有狀態，作答工作區必須保持隱藏，且題目內容不得被渲染。
- **FR-111**：缺少 `token` 時**不得**發出任何 API 請求。

#### 作答介面

- **FR-112**：工程類部門必須提供程式碼編輯器、語言選擇（JavaScript／Python／Go／Java／C++）、
  標準輸入欄位、試跑按鈕與執行結果區塊。
- **FR-113**：非工程類部門必須提供文字作答區，且不得顯示語言選擇、試跑按鈕、
  標準輸入與執行結果區塊。
- **FR-114**：程式碼編輯器載入失敗時必須退回純文字輸入框，作答與提交能力不受影響。
- **FR-115**：切換語言時，已輸入的作答內容不得遺失。
- **FR-116**：題目描述、限制條件與範例測資必須以文字方式寫入 DOM，不得以字串拼接 HTML。

#### 試跑

- **FR-117**：試跑結果必須顯示標準輸出、錯誤輸出、終止原因的中文說明與執行耗時；
  輸出被截斷時必須明確標示。
- **FR-118**：試跑成功後剩餘次數減一並即時更新；次數為 0 時試跑按鈕停用，
  提交按鈕**不得**受影響。
- **FR-119**：試跑回應 429 時，剩餘次數歸零並停用試跑按鈕，提交仍可用。
- **FR-120**：試跑回應 503 時顯示沙箱不可用訊息並告知仍可提交，且剩餘次數不得被扣減。
- **FR-121**：試跑回應 409（已提交）或 410（逾期）時，畫面必須轉入對應的終端狀態。
- **FR-122**：試跑請求進行中必須停用試跑按鈕，避免重複送出。

#### 提交

- **FR-123**：提交前必須有明確的確認步驟，內容須告知提交後不可修改。
- **FR-124**：取消確認時不得送出任何請求，且作答內容不得改變。
- **FR-125**：提交成功後必須隱藏工作區並顯示含提交時間的成功確認。
- **FR-126**：提交回應 409 時畫面必須轉為已提交狀態；410 時必須轉為逾期狀態。
- **FR-127**：提交請求進行中必須停用提交按鈕，避免重複送出。

#### AI 助教

- **FR-128**：頁面載入時必須以 session 回傳的對話歷程還原對話區內容。
- **FR-129**：助教模組的任何失敗只能寫入其自身的錯誤區塊，**不得**向外拋出，
  亦不得停用作答、試跑或提交。
- **FR-130**：對話請求進行中必須避免重複送出。
- **FR-131**：對話模組必須可掛載於呼叫端提供的容器元素，不得於模組載入時直接抓取
  全域 DOM。

#### 資料最小化

- **FR-132**：應徵者介面呈現的資料必須限於白名單欄位；即使 API 回應含有額外欄位，
  也不得被渲染或寫入 DOM。
- **FR-133**：應徵者介面的原始碼**不得**出現 AI 報告、主管內部評語、決策結果或
  隱藏測資的欄位名稱與存取路徑。
- **FR-134**：token 不得被寫入頁面可見文字、不得被寫入 `localStorage`／`sessionStorage`，
  也不得出現在錯誤訊息中。

### 非功能需求

- **NFR-001（相容性）**：本次變更**不得**修改任何 candidate API 的路徑、請求／回應結構、
  狀態碼語意或安全模型。後端 `backend/tests/contract/test_candidate_*.py` 四份契約測試
  必須在零修改的情況下全數通過。
- **NFR-002（不破壞既有角色）**：HR 與主管介面的行為與檔案內容不得因本次變更而改變，
  其既有測試必須全數通過。
- **NFR-003（無建置流程）**：不得引入前端打包或轉譯流程；瀏覽器直接載入原生 ES 模組
  的既有決策（上游 research.md R-004）維持不變。
- **NFR-004（離線測試）**：新增的前端測試必須可在無網路、無瀏覽器、無外部服務的環境中執行，
  且不得引入需自 npm 安裝的執行期或測試期相依套件。
- **NFR-005（可讀性）**：單一 JS 模組不超過約 150 行，且每個模組只有一個責任；
  純邏輯與 DOM 操作必須分屬不同檔案。
- **NFR-006（無障礙）**：作答區、題目區、執行結果與對話區必須具備可辨識的區域標示，
  狀態提示必須能被輔助技術讀取。
- **NFR-007（韌性）**：任何外部 CDN 資源載入失敗時，核心作答流程必須仍可完成。

### 不變條件（Invariants）

以下條件在本功能的任何後續變更中皆必須成立，並由自動化檢查守護：

- **INV-001**：`frontend/candidate/` 內的任何檔案都不含 `fetch(` 字面呼叫。
- **INV-002**：`frontend/candidate/` 不匯入 `frontend/js/hr.js` 或 `frontend/js/manager.js`；
  反向亦然。
- **INV-003**：`frontend/candidate/` 自 `frontend/js/api.js` 匯入的識別字，
  是「candidate 允許清單」的子集。
- **INV-004**：`frontend/candidate/` 的**出貨**原始碼（`tests/` 以外）不含 `dimensions`、
  `internal_comment`、`ai_report`、`manager_decision`、`is_hidden`、`test_cases`
  等受限識別字。`tests/` 排除在外，因為那裡的受限識別字是用來證明視圖模型會丟棄它們的
  刻意污染輸入。
- **INV-005**：`/candidate/session/{token}` 永遠回傳 API JSON，不被靜態檔案遮蔽。
- **INV-006**：`/assessment.html` 與 `/candidate/assessment.html` 皆可被服務（HTTP 200）。
- **INV-007**：純邏輯模組（`frontend/candidate/core/`）不引用 `document`、`window`、
  `fetch` 或 `localStorage`，因此可於 Node 環境直接匯入測試。
- **INV-008**：candidate API 的四份後端契約測試檔案內容不因本功能而修改。

## 假設

- **後端無需變更**：candidate 的四個端點已完整覆蓋本規格所需的全部資料與錯誤語意
  （session 載入含 `chat_history`、run 的 429／503／409／410、submit 的 409／410）。
  頁面路徑由環境變數 `CANDIDATE_BASE_URL` 決定，非寫死於程式碼，因此路徑變更亦不需
  改動後端程式。詳細論證見 [plan.md](plan.md)「後端不變更的理由」。
- **樣式自帶，不依賴 CSS CDN**：`frontend/candidate/css/candidate.css` 隨頁面出貨，
  不引入 CSS 建置流程，也不使用 Tailwind CDN（見「v2 視覺改版」）。
- **既有連結的效期**：舊路徑轉址頁的保留期至少涵蓋最長 token 效期（7 天）；
  是否移除為日後的獨立決策，本規格不設移除時程。
- **測試執行器**：純邏輯模組以 Node 內建的 `node:test` 執行（Node 18+ 內建，零安裝）；
  結構性不變條件以既有的 pytest 套件守護，維持單一 CI 指令集。

## v2 視覺改版（2026-08-03）

依 Claude Design 交接的「Candidate Answer Screen」設計稿改為深色主題與左右兩欄版面。
**模組邊界、API 呼叫路徑與 core/ 的判定邏輯完全未動**；改動範圍限於標記、樣式與
ui/ 層的 class 字串。

### 新增需求

- **FR-135**：版面為左右兩欄——左欄由上而下為題目、作答、執行結果；右欄為 AI 助教對話。
- **FR-136**：提交按鈕位於頁首右上角，與作答區分離。
- **FR-137**：`READY` 以外的狀態，頁首中「只在作答期間有意義」的控制項
  （提交按鈕、剩餘試跑次數、連結到期時間、作答中標示）必須一併隱藏。
  只隱藏工作區並不足夠——提交按鈕在頁首，會留下一顆按了必定失敗的按鈕。
- **FR-138**：樣式表必須隨頁面出貨，不得依賴 CSS CDN。
- **FR-139**：AI 助教對話框支援 Enter 送出、Shift+Enter 換行。
- **FR-140**：AI 助教提供常見問題捷徑；捷徑必須走與手動送出完全相同的請求路徑，
  不得另闢 API 呼叫管道。
- **FR-141**：提交確認視窗必須顯示即將送出的作答字數。

### 新增不變條件

- **INV-009**：`ui/elements.js` 查找的每一個 id 都必須存在於 `assessment.html`。
  這是改版時最容易發生的退化：JS 拿到 `null`，畫面只是「某塊沒東西」，不會拋錯。
- **INV-010**：`assessment.html` 不得引用 `cdn.tailwindcss.com`，且必須引用
  本地樣式表 `./css/candidate.css`。

### 刻意未採用設計稿的部分
